Что умеет магазин

Две роли: покупатель, который выбирает и платит, и владелец, который управляет каталогом и заказами.

Покупатель

  • Каталог с фильтрами по категории, материалу, цвету, размеру и цене
  • Поиск и сортировка по популярности и скидке
  • Карточка товара с остатками по размерам и отзывами
  • Избранное и корзина
  • Оформление и оплата через СБП
  • Личный кабинет с историей заказов

Владелец

  • Редактор товаров с загрузкой фото
  • Управление заказами и пользователями
  • Модерация отзывов
  • Запуск парсера каталога и состояние сервисов
  • Новые заказы приходят в Telegram, статус меняется кнопками прямо в чате
  • Админка на SQLAdmin для работы с базой

Технические решения

Места, где у магазина есть реальные сложности: деньги, остатки, повторные запросы и сбои.

Резервирование остатков

Заказ списывает остаток сразу, под блокировкой строк размеров (SELECT ... FOR UPDATE). Строки блокируются в фиксированном порядке, поэтому два заказа с общими позициями не создают взаимную блокировку.

Автоотмена заказов

Неоплаченный заказ отменяется воркером через 30 минут, остаток возвращается на склад.

Явная машина статусов

Допустимые переходы заданы таблицей, всё остальное отклоняется. Повторные вебхуки и гонки не откатывают статус.

Идемпотентные вебхуки оплаты

Каждое событие записывается в payment_events, повторная доставка возвращает duplicate и ничего не меняет. В боевом режиме статус и сумма запрашиваются у ЮKassa. Оплата по уже отменённому заказу уходит владельцу на ручной разбор.

Безопасность

Access и refresh токены с привязкой к сессии, ограничение частоты запросов через Redis, чужой заказ возвращает 404 вместо 403. В режиме production сервер не стартует со слабыми секретами и тестовыми ключами.

Наблюдаемость

Метрики Prometheus, дашборд Grafana, структурированные логи с идентификатором запроса, /health с проверкой БД, Redis, S3 и Telegram.

Архитектура

Браузер работает с одним адресом. nginx направляет /api, /media, /docs и /sqladmin в FastAPI, остальные запросы во фронтенд. Поэтому при локальном запуске CORS не используется.

Пунктирная рамка означает внешний сервис. Контейнер migrate применяет миграции Alembic перед стартом API.

Запуск

Нужен Docker с Compose 2.23 или новее. Миграции применяются автоматически перед стартом API.

git clone https://github.com/asas-poq/Kochevnik-Store.git
cd Kochevnik-Store

cp backend/.env.example backend/.env
docker compose up -d --build
make seed

Команда make seed создаёт двух пользователей, запускает парсер и загружает в каталог 50 товаров. Это занимает несколько минут, потому что парсер делает паузы между запросами.
