# Kochevnik Store: фронтенд

Витрина, личный кабинет и админка интернет-магазина. Next.js 16 (App Router), React 19, TypeScript, Tailwind 4, shadcn/ui, zustand, TanStack Query, axios, react-hook-form и zod.

## Как создавался фронтенд

Я специализируюсь на бэкенде. Дизайн пяти экранов витрины (главная, каталог, карточка товара, корзина, оформление заказа) я нарисовал в [Figma](https://www.figma.com/design/SdLZRSgUdizjPyxh0Rj6v7/Untitled?node-id=0-1). Код фронтенда сгенерирован с помощью ИИ по этим макетам, после чего я подключил его к API: клиент с обновлением токенов, типы по `openapi.json`, корзина, формы и обработка ошибок. Остальные экраны (вход, регистрация, профиль, админка) выполнены в том же стиле.

## Запуск

Требуется Node.js 22. Бэкенд должен быть запущен, иначе каталог будет пустым: инструкция в [корневом README](../README.md).

```bash
cd frontend
cp .env.example .env.local
npm install
npm run dev
```

Сайт откроется на http://localhost:3000.

| Переменная | Назначение |
|---|---|
| `NEXT_PUBLIC_API_URL` | Адрес бэкенда без `/api/v1`. Для Compose из корня репозитория `http://localhost`, для API на порту 8000 значение из `.env.example` |
| `NEXT_PUBLIC_SITE_URL` | Адрес сайта, используется в метаданных страниц |

Обе переменные встраиваются в код при сборке, после изменения требуется перезапуск `npm run dev` или пересборка образа.

## Структура

```
src/
  app/          страницы: главная, каталог, товар, корзина, оформление, заказ, профиль, вход, админка
  components/   компоненты по разделам, базовые в ui/ (shadcn)
  hooks/        запросы к API через React Query
  stores/       auth-store (сессия), cart-store (корзина)
  lib/          api.ts (клиент), константы, форматирование, ключи запросов
  types/        типы API, сгенерированные по openapi.json
public/images/
  home/         фото главной страницы
```

## Особенности реализации

**Ошибки API.** Бэкенд возвращает `{detail, code}`. Клиент в `lib/api.ts` преобразует ответ в `ApiError`, пользователю он показывается уведомлением sonner.

**Сессия.** Хранится в zustand и сохраняется в localStorage. При ответе 401 клиент один раз обновляет токен через `/auth/refresh` и повторяет запрос. Если обновление не удалось, пользователь выходит из системы. Параллельные запросы, получившие 401, ожидают один общий refresh.

**Корзина** локальная, в zustand. Бэкенд получает уже сформированный заказ, а цены и остатки при этом перепроверяются на сервере.

**Админка** (`/admin/*`) доступна только роли `admin` и намеренно отличается от витрины: холодная палитра, боковое меню, таблицы.

**Оформление.** Тёмная тема через next-themes, вёрстка сначала для телефона, цены форматируются как `12 500 ₽`. Цвета и шрифты заданы переменными в `src/app/globals.css`, тему можно менять в одном месте.

**Контракт с бэкендом.** При изменении API обновляются `openapi.json` и типы в `src/types/api.d.ts`.
